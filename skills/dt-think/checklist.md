# 方案检查清单

dt-think 设计方案、dt-dev-review 检查代码共用这一份清单，其他地方只引用，不复制条目。

范围与约束、方案对比、影响范围、验收标准由 design.md 的固定章节负责（见 dt-think「阶段二」），本清单只列这些章节之外容易漏的方面。

| # | 方面 | 要回答的问题 |
|---|---|---|
| 1 | 兼容 | 这次碰到的现有接口、字段、表、CLI 参数和输出、配置格式，老调用方、旧版本、已有数据还能不能正常用？哪些现有行为必须保持不变？ |
| 2 | 状态 | 业务状态怎么切换，会不会乱跳或卡在中间？页面在加载中、空数据、部分失败、出错、成功时各显示什么？依赖异步加载的内容，就绪顺序变了会怎样？ |
| 3 | 异常与依赖失败 | 空值、超长、格式不对、超上限、时区和跨天怎么处理？下游服务、第三方、宿主页面变慢、失败，或它们的数据被删改时，是降级还是报错，用户看到什么？只成功一半、超时后不知道成没成功怎么办？出错后果严重的操作（拦截用户操作、删数据、扣钱），判断条件是否比普通操作更严？ |
| 4 | 重复与并发 | 同一个写操作执行两次（连点、重试、Webhook 重推、超时后重提）结果对不对？提交中能不能再点，失败后用户填的内容还在不在？两个请求同时改同一条数据，或旧请求晚返回覆盖新结果，会怎样？ |
| 5 | 权限与安全 | 谁能用？没权限的人（包括别的店铺）直接调接口能不能绕过？敏感数据会不会出现在前端、日志、URL 或对外文档里？ |
| 6 | 数据量、性能与缓存 | 单个店铺最多多少数据，要不要分页、批量或后台异步？会不会比现在慢，会不会把压力转到别的服务？有哪些缓存或派生数据，源数据变了或写操作之后谁来作废，多层叠加后实际要多久才更新？ |
| 7 | 环境与验证范围 | 依赖的工具、组件、服务、文件，在目标环境（CI、镜像、dev/stg/生产、用户机器）里的版本和行为是否和本机一致？第三方和宿主的真实行为实测过没有？这次在哪些主题、端、语言、数据形态、入口下验证，没验到的写进风险。 |
| 8 | 上线、回退与排查 | 要不要灰度、开关、数据迁移、人工操作？新版本怎么生效到已打开的页面、已安装的店铺？新旧代码和数据同时存在时能否正常工作？出问题怎么退回，退回后数据对不对？靠什么日志、埋点、监控发现和定位问题？ |

## 方案阶段

逐条判断：

- 涉及的写进 design.md 的「方案」；验证不到、或决定接受不处理的写进「风险」。
- 拿不准的写"待确认"，不要猜。
- 不涉及的在「方案」末尾写一行"不涉及：第 X、Y 条"。

## 检查代码阶段

按 8 条逐条看 diff。方案标了"不涉及"的条目也要看，确认改动里确实没碰到。只报影响正确性的问题，不报风格。方案有没有做全、有没有超出范围，由功能符合性检查负责，这里不重复查。

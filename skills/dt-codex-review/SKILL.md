# Codex 方案评审

## 配置（本 skill 唯一一处）

- 模型：`gpt-6.2-sol`
- 推理档位：`xhigh`

方案评审用的模型和档位只改这里（dt-dev-review 的代码审查另有一份）。

## 输入与输出位置

- 方案文件：必填，绝对路径。dt-dev 调用时是 `<任务目录>/design.md`；单独使用时用户没给就问。
- 项目目录：方案涉及的代码仓库根目录，默认当前项目根目录。方案有「涉及仓库」节时，其余仓库的绝对路径写进提示词，让 Codex 一起读。
- 输出目录：`<方案文件所在目录>/codex-review/`，每轮四个文件：
  - `round-N-plan.md`：本轮送审的方案副本
  - `round-N-prompt.md`：发给 Codex 的提示词
  - `round-N-codex.md`：Codex 原始意见
  - `round-N-verdict.md`：Claude 复核结果

判据以同目录的 `criteria.md` 为准，Codex 和 Claude 都按它判断。

## 每一轮

1. **定轮次**：输出目录里已有 `round-N-codex.md` 的最大 N，本轮是 N+1。N 已经是 3 时不再评审，告诉用户已到上限，展示第 3 轮的复核结果。
2. **存副本**：把方案文件复制为 `round-N-plan.md`。
3. **组提示词**：`round-N-prompt.md` 依次拼接三段：
   - 本 skill 目录下 `prompt.md` 全文；
   - `## 评审判据` 加 `criteria.md` 全文；
   - `## 本轮信息`：方案文件（`round-N-plan.md` 的绝对路径）、项目目录、其他涉及仓库。复审轮再加两项：
     - `### 本轮改动`：`diff -u round-(N-1)-plan.md round-N-plan.md` 的输出；
     - `### 历史意见`：之前每一轮 `round-*-verdict.md` 的绝对路径。
4. **后台运行 Codex**，等结束通知，不轮询：

   ```bash
   codex exec -m <模型> -c model_reasoning_effort="<档位>" -s read-only -C <项目目录> --skip-git-repo-check --ephemeral -o <输出目录>/round-N-codex.md - < <输出目录>/round-N-prompt.md
   ```

   退出码不为 0，或 `round-N-codex.md` 不存在、为空：把报错原文告诉用户，停下等用户决定，不拿上一轮结果代替。

5. **Claude 复核**，写入 `round-N-verdict.md`：
   - 只复核 Codex 提出的条目，不另外加自己的新问题。
   - 每条亲自核实：读方案、读代码、查文档。不因为是 Codex 提的就默认对，也不因为方案是自己写的就护着。
   - 按 `criteria.md` 判定，三选一：
     - **采纳**：确实属于判据 6 类之一，且后果成立；
     - **不采纳**：不属于判据范围、后果不成立、依据核实不了，或和已有意见重复；
     - **原有问题**：不是这次方案引入的，不改，列为待办。
   - 文件格式：第一行 `结论：采纳 X 条，不采纳 Y 条，原有问题 Z 条`，下面一张表：

     | # | Codex 意见（一句话） | 判定 | 理由和依据（文件:行号 / 方案章节 / 文档出处） |
     |---|---|---|---|

     复审轮在表前加一行写上一轮采纳项的处理情况（Codex 说改好了的，Claude 也要核实）。

6. **给用户看**：本轮结论、采纳清单（编号）、不采纳项各一句理由、原有问题待办。等用户确认要改哪几条，不确认不改。
7. **改方案**：只改用户确认的条目；同类问题列出的位置全部改。
8. **决定下一步**：
   - 本轮没有采纳项，或用户一条都不改 → 结束，结论「评审通过」。
   - 有改动且本轮不到第 3 轮 → 直接进入下一轮复审，不再问。
   - 第 3 轮仍有采纳项 → 停止评审，列出剩余问题，提醒用户：连续 3 轮都有重要问题，可能是方案思路本身要换。问用户选哪个：按清单改完收尾、回头换方案思路、接受风险不改。

## 结束输出

第一行写结论「评审通过」或「评审未通过」，再写：共 N 轮，采纳 X 条（已改 / 未改），不采纳 Y 条，原有问题 Z 条；最后给出输出目录路径。
